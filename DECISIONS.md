# DECISIONS — отклонения от плана и выборы (дата, что, почему)

- 2026-10-22 · Публикация сайта: сборка на ноутбуке и принудительная отправка `dist/` одним коммитом в ветку `gh-pages` (скрипт `scripts/deploy.mjs`), а не GitHub Actions. Почему: у ключа `gh` права `repo, gist, read:org`, без `workflow` — файл workflow не запушить. Один коммит на публикацию — чтобы старые сборки и куски модели не копились в истории ветки.
- 2026-10-22 · Тест-страница iPhone, шаг 5: модели грузятся прямо с Hugging Face (только на тест-странице; само приложение внешних адресов, кроме api.github.com, не использует). Qwen2.5-0.5B-Instruct Q4_K_M — официальный репо `Qwen/Qwen2.5-0.5B-Instruct-GGUF` (491 МБ, Apache-2.0); Qwen3-0.6B Q4_K_M — у Qwen официально только Q8_0, поэтому `unsloth/Qwen3-0.6B-GGUF` (397 МБ, Apache-2.0). Обе ссылки отвечают 200 и `access-control-allow-origin: *` (проверено curl 2026-10-24).
- 2026-10-24 · `llama-gguf-split` поставлен через `winget install ggml.llamacpp` (официальный пакет llama.cpp, сборка b11804); путь: `%LOCALAPPDATA%\Microsoft\WinGet\Packages\ggml.llamacpp_Microsoft.Winget.Source_8wekyb3d8bbwe\llama-gguf-split.exe`.
- 2026-10-24 · Этап 4, отступления от плана (копия на GitHub): (1) новый телефон с пустой базой НЕ перезаписывает копию в GitHub, пока устройство не сделало первую успешную копию или восстановление (флаг `backup_linked`); иначе владелец, вставив токен, стёр бы старую копию раньше, чем нажмёт «Восстановить». (2) Месяц файла = месяц `created_utc` по UTC (стабилен). (3) При восстановлении кошелёк из копии заменяет такой же по id (у кошельков нет метки времени); записи — по самому новому `updated_utc`, при равенстве остаётся локальная. (4) У запросов к GitHub нет опции `cache` и лишних заголовков: Safari из `cache:'no-store'` делает заголовки Cache-Control/Pragma, которых нет в разрешённых заголовках CORS у GitHub. (5) `check:build` проверяет только то, что достижимо из приложения (не `dist/test/` и не куски тест-страницы): страница теста ходит на huggingface.co.
- 2026-10-24 · Модели для этапа 5 пережаты из исходных F16/BF16 (готовые Q4_K_M с Hugging Face не режутся на куски < 100 МБ: у Qwen3 таблица слов 127 МБ, у Qwen2.5 таблица слов и выходной слой по 138 МБ). Qwen3-0.6B: `llama-quantize --token-embedding-type q4_k <bf16> <out> Q4_K_M` → 357 МБ, 4 куска 83–95 МБ. Qwen2.5-0.5B: размер 896 не делится на 256, поэтому `--token-embedding-type q5_0 --output-tensor-type q5_0 ... Q4_K_M` → 434 МБ, 5 кусков 59–99,5 МБ. Нарезка: `llama-gguf-split --split --split-max-size 95M`. Качество сравнивается на тех же 50 фразах (этап 5).
- 2026-10-25 · Этап 4, проверка безопасности: исправлено — при восстановлении поля записи с неверным типом отбрасываются (`sanitizeFields`), иначе испорченная копия ломала бы списки и итоги. Принято как риск, не делаем сейчас: (1) приложение не проверяет, что `pocket-brain-data` приватный (владелец в настройки репозитория не ходит; лишний запрос менял бы весь поток копирования); (2) запись с `updated_utc` из будущего в копии всегда побеждает при слиянии; (3) кошельки из копии заменяют локальные без метки времени (описано в `restore.ts`).
