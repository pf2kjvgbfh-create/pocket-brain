# DEVELOPMENT.md — как развивать POCKET-BRAIN после MVP

## Карта проекта (исполнитель обновляет `docs/CODEMAP.md` после этапов, где менялась структура)
- `src/parser/` — разбор русского текста: `normalize.ts` (числа словами), `time.ts` (chrono-node ru, +03:00), `money.ts`, `rules/<тип>.ts` (по файлу на тип записи), `index.ts` (`parse`).
- `src/model/` — wllama-compat, очередь, грамматика JSON, слияние «только заполнять пустое».
- `src/db/` — IndexedDB, миграции, схема записей.
- `src/backup/` — копия на GitHub, восстановление, экспорт, делитель по месяцам.
- `src/ui/` — вкладки, карточка «Понял так», списки; `src/shortcut/` — формат данных для Команды.
- `tests/fixtures/phrases.ru.json` — 50 эталонных фраз (это и есть спецификация разбора, и набор для оценки модели).
- `public/model/` — куски модели (только победитель), `public/test/` — страница проверки iPhone, `docs/` — решения и замеры.

## Новый тип записи (например «долг», «привычка»)
1. Владелец одной фразой: что за тип, 3 примера фраз и что должно быть видно в списке.
2. Тесты сначала: добавить 4–6 фраз в `phrases.ru.json` с ожидаемым результатом (имена и суммы выдуманные).
3. `src/db/`: добавить значение в `kind`, поля — в `fields`; миграция версии IndexedDB, старые записи не трогать (тест: старая база открывается).
4. `src/parser/rules/<тип>.ts` + регистрация в `index.ts`; порядок правил = приоритет, неуверенный разбор остаётся `idea`.
5. `src/ui/`: строка списка и поля карточки. Копия на GitHub подхватит автоматически (список полей — в allowlist сериализатора: добавить поле явно, иначе в копию не попадёт).
6. Обновить схему в `docs/CODEMAP.md`, прогнать все тесты и Playwright на 375 px (WebKit + Chromium), коммит `feat: тип <имя>`.

## Новое правило разбора (слово-маркер, пример фразы, сумма, пояс)
1. Пришла фраза, которую приложение поняло неверно → добавить её в `phrases.ru.json` с ПРАВИЛЬНЫМ ожидаемым результатом; тест должен упасть.
2. Исправить в `src/parser/` самым узким правилом; все 50+ фраз остаются зелёными (нельзя ослаблять ожидания).
3. Если правило про время — проверить тестами с `TZ=UTC` и `TZ=America/New_York`: результат не зависит от пояса телефона.
4. Если правило меняет формат поля — миграция данных не нужна, пока поле остаётся в схеме; иначе см. «Новый тип записи», п. 3.
5. Если фраза не ловится правилами, а модель её понимает — это не повод убирать правило: модель только дополняет (invariant: RULES FIRST).

## Другая модель
Новая модель — только после запуска той же оценки на 50 фразах (`docs/model-eval.md`) и проверки на телефоне тест-страницей: потолок памяти и ток/с. Куски < 100 МБ; в репо только один победитель; старые куски удалять из `public/model/` (история git их хранит — следить за размером репо).

## Баг
1. Владелец: что сказал/сделал, что ожидал, что увидел (скриншот).
2. Чат: воспроизвести тестом ДО правки (для разбора — фраза в фикстуру). Не воспроизвёл — спросить, не чинить вслепую.
3. Исправить, тест остаётся, коммит `fix: …`, строка в `LESSONS.md`, если причина системная.

## Когда делать `/clear`
После каждого закрытого этапа или фичи; когда чат забывает договорённости; перед крупным куском (миграция, новая модель). STATUS.md — всё для продолжения: «продолжай POCKET-BRAIN».

## Что никогда не трогать без архитектора
- Правила токена: хранение, allowlist копии, отсутствие в логах.
- Однопоточный режим модели и флаг `model_loading` (защита от вылета iOS).
- Чтение `#t=` один раз + `replaceState` + id записи (защита от дублей).
- Формат данных для Команды «Мозг-напомнить» (`due`, `due_local`) — Команда на телефоне собрана вручную, её не обновить из кода.
- Правило «все времена по МСК, хранение в UTC».

## Когда возвращаться к архитектору
Новая интеграция (банк, синхронизация с PAY-REMINDER, речь в странице, граф связей); блокер дольше одной сессии; одна ошибка дважды → `/retro`. Форма обращения: скопировать `STATUS.md` и последний отчёт чата в чат архитектора.

## Ручные проверки владельца после любого изменения (с телефона)
1. Открыть ссылку из кнопки: текст попал в поле, карточка «Понял так» появилась.
2. Сохранить запись, обновить страницу: запись одна, не две.
3. Настройки → «последняя копия» показывает свежее время по МСК.
